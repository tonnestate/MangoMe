LUNA / CODEX P0 HANDOFF — MangoMe v0.3.14

GitHub main is the only source truth after the v0.3.14 web upload.

GOAL
Convert the existing single-host deployment to LOCAL_HOST, delete obsolete MangoMe
credential residue, restore health, then perform the already-authorized MangoMe total
database reset.

HARD SAFETY BOUNDARY
- Never touch a non-MangoMe database.
- Never delete or edit MongoDB dbPath files.
- Never start a temporary --noauth mongod.
- Never create a MongoDB user or role.
- Never expose MongoDB beyond loopback.
- If MongoDB is not loopback-only, STOP before disabling authorization.
- Do not change unrelated client configuration.

PHASE 1 — UPDATE
1. Update the existing MangoMe checkout exactly to GitHub main.
2. Reinstall the existing MangoMe environment from that checkout.
3. Confirm installed version is 0.3.14.

PHASE 2 — DELETE OBSOLETE MANGOME CREDENTIAL RESIDUE
Remove only if present:
- ~/.config/mangome/mongodb-uri
- ~/.config/mangome/mongodb-maintenance-uri
- ~/.config/mangome/database-binding.json

From MangoMe entries only in managed Claude/Codex configuration, remove stale keys:
- MANGOME_MONGODB_URI_FILE
- MANGOME_MONGODB_URI
- MANGOME_ADOPT_EXISTING_DATABASE
- MANGOME_ZERO_TOUCH_LOCAL_PROVISION

Do not delete unrelated configuration.
Keep/set:
- MANGOME_TRUST_BOUNDARY=LOCAL_HOST
- MANGOME_DATABASE=mangome
- MANGOME_EXPECTED_DATABASE=mangome
- MANGOME_ZERO_TOUCH_BOOTSTRAP=1
- MANGOME_ALLOW_EVAL_DATABASE=0

PHASE 3 — ONE-TIME HOST MIGRATION
1. Read the active MongoDB service and /etc/mongod.conf.
2. Before changing authorization, prove the active MongoDB listener is loopback-only.
   Accept only 127.0.0.1 / localhost / ::1.
   If any non-loopback bind/listener exists: STOP. Do not disable authorization.
3. Make one timestamped backup of /etc/mongod.conf.
4. Change only MongoDB authorization for this deployment to disabled.
   Preserve loopback-only binding and all unrelated MongoDB settings.
5. Restart the existing mongod.service exactly once to apply this host configuration.
6. Verify again that the listener remains loopback-only.

PHASE 4 — READINESS
Run the installed v0.3.14:
  mangome health

Required before reset:
- version = 0.3.14
- process_ready = true
- database_ready = true
- trust_boundary.mode = LOCAL_HOST
- trust_boundary.credential_source = NONE
- trust_boundary.endpoint_scope = LOOPBACK
- database = mangome

If any condition fails: STOP. Do not improvise.

PHASE 5 — EXPLICIT TOTAL RESET
The owner already authorized this MangoMe-only reset in the current recovery task.

Run exactly:
  mangome database-reset --confirm TOTAL-RESET-MANGOME-DATABASES

The implementation itself must report:
- exact allowlist = mangome, mangome_uai_eval
- no MongoDB service restart by MangoMe
- no wildcard matching
- no credential/user/role bootstrap
- non-target database preservation verified

Legacy rule:
- mangome_uai_eval must never be adopted/repaired/migrated.
- It may only be deleted by this explicit reset because schema drift is fail-closed.

PHASE 6 — FINAL CHECK
Reload/restart only the MangoMe MCP/client process as needed; do not restart MongoDB.
Run:
  mangome health

Report:
- Git commit
- installed MangoMe version
- MongoDB listener scope
- authorization mode
- deleted MangoMe databases
- non-target preservation verification
- final health
