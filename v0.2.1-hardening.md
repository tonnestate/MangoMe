# MangoMe v0.2.1 Hardening

Base: `tonnestate/MangoMe` `main` commit `10c7859826a0fa379e99ffbcada0321eb1c36560` (`v0.1.9rc4`).

This release closes an observed assignment-execution failure: an agent given an audit assignment returned a new audit contract/planning artifact instead of executing the audit. MangoMe now distinguishes internal execution organization from the human-visible result more explicitly.

## Assignment execution invariants

- Existing Slices are reused. Assignment preparation never duplicates them.
- If an admitted Family has no Slice, MangoMe may materialize the minimum internal Slice needed to execute the assignment.
- Slices and Plans are internal execution state and are not normal user-facing output.
- Planning, checklists, specifications, or newly authored contracts do not constitute completion of an audit/review/verification assignment.
- Audit/review work cannot claim `DONE_CLAIMED` without persisted non-claim Evidence.
- Audit/reconciliation observes and records the normative-versus-observed delta before repair/adaptation/correction. Explicit read-only work remains read-only.
- Contract/Specification truth is not rewritten merely to make implementation conform.

## Runtime and data hardening

- Managed client configuration pins the expected MongoDB database. A client selecting a different database fails closed with `WRONG_MANGOME_DATABASE`.
- Reader-side schema handling fails closed on future document schema versions rather than silently interpreting them with an older reader.
- Graph reads use indexed `from_id` / `to_id` queries instead of broad Edge collection scans. Mongo adds the reverse `to_id` index and an Evidence subject index.
- Family context reads use bounded database predicates for Evidence and graph edges.

## Context envelope

`ContextCompiler` supports a deterministic hard byte envelope. Canonical truth is never truncated. When the disposable execution projection exceeds the envelope, optional Evidence payload detail and Contract storage detail are compacted first, then old Evidence entries are omitted. If mandatory normative/execution state still does not fit, compilation fails closed with `ContextBudgetExceeded`.

A byte envelope is intentionally used instead of pretending MangoMe can guarantee provider-specific token counts without the exact target tokenizer. Provider-reported token counts remain Execution Receipt telemetry.

## Scope deliberately not added

v0.2.1 does **not** add an in-memory graph cache or MongoDB Change Stream mirror. The current repository still contains avoidable broad graph reads, so query/index correction is the first step. A second graph truth/cache would be premature while runtime/database identity is being hardened.
