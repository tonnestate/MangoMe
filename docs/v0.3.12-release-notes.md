# MangoMe v0.3.12 — v0.3.11 Repair & External Enforcement Boundary

Release date: 2026-09-29

v0.3.12 repairs the concrete regressions found after v0.3.11 and tightens the boundary between MangoMe governance and physical runtime enforcement. It deliberately does not introduce cryptographic key management.

## Worker facade repair

- Keeps exactly seven normal worker MCP tools.
- Restores semantic routing for all 100 pre-existing advanced v0.3.11 capabilities.
- Restores the 46 capabilities that v0.3.11 accidentally made unreachable from the normal worker path.
- Keeps the advanced/internal MCP endpoint available explicitly rather than expanding the normal surface again.
- Preserves weak-agent guidance: `disposition`, `recommended_next_action`, `allowed_next_actions`, `forbidden_next_actions`, and `reason_codes`.

## Structural repair

- Prefers `tree-sitter-language-pack.get_parser(...)` where available.
- Adapts str/bytes parser input and `type`/`kind`, byte-range and position differences.
- Retains the standalone Tree-sitter fallback where interoperable.
- Retains bounded text fallback and non-blocking `STRUCTURAL_CONTEXT_UNAVAILABLE` behavior.
- Corrects architecture wording: PCH/1 and SRA/1 remain authoritative for their own persisted/deterministic state; structural projections are advisory data beside them.

## External enforcement boundary

MangoMe does not become an OS sandbox. A host/router may apply an external enforcement backend after MangoMe authorizes delegation. The worker cannot widen that host policy.

Enforcement provenance can use the existing `record_execution_receipt(..., metadata=...)` field with keys such as:

- `enforcement_backend`
- `enforcement_version`
- `policy_ref`
- `policy_digest`
- `audit_ref`
- `enforcement_decision`

These values are provenance/observations, not truth or assurance. Independent material claims still flow through existing Evidence and AV/1 semantics.

## Explicit non-goals

v0.3.12 does not add HMAC, key files, key rotation, a cryptographic mutation journal, blockchain/consensus, a new Mongo schema, `nono`, OpenShell, LlamaFirewall, Inspect AI, NeMo Guardrails, or a second governance layer. External components are evaluated outside the MangoMe runtime first.
