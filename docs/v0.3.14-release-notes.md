# MangoMe v0.3.14 — LOCAL_HOST Trust & Legacy Schema Fail-Closed

## P0 objective

Remove the v0.3.12/v0.3.13 credential/bootstrap deadlock for the intended managed
single-host deployment without ever stopping a shared MongoDB service from MangoMe.

## Managed-local trust model

- MongoDB listener must be loopback-only.
- MongoDB authorization is disabled for this deployment profile.
- MangoMe uses no MongoDB username, password, role or credential file.
- No maintenance identity exists.
- No credential discovery or credential adoption occurs.
- MangoMe never edits `mongod.conf`, firewall policy or host networking itself.

This moves the deployment trust boundary to the Linux host. It is not suitable for
remote MongoDB listeners or an untrusted multi-user host.

## Legacy database rule

Legacy databases are rejected for runtime use because schema drift is not safe to
repair implicitly.

`mangome_uai_eval` therefore has these semantics:

- never auto-adopt;
- never auto-repair;
- never auto-migrate;
- never become canonical runtime state;
- may be deleted only by the explicitly confirmed exact-allowlist total reset.

The stable failure code for attempted legacy runtime selection is:

```text
LEGACY_DATABASE_SCHEMA_DRIFT
```

## Reset invariants

The exact destructive allowlist is:

```text
mangome
mangome_uai_eval
```

The reset must verify LOCAL_HOST before mutation and must never:

- wildcard-match database names;
- stop/start/restart MongoDB;
- run a temporary `--noauth` mongod;
- touch MongoDB `dbPath`;
- create MongoDB users or roles;
- mutate non-target databases.

After reset, MangoMe recreates only canonical indexes in `mangome` and verifies that
the set of non-target database names is unchanged.

## Migration note

Old MangoMe credential artifacts and managed-client credential bindings are obsolete
for LOCAL_HOST and should be removed during the one-time host migration.
