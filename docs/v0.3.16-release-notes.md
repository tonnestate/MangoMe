# MangoMe v0.3.16 — Zero-Touch LOCAL_HOST Activation & Cleanup

v0.3.16 is a deployment-repair release. It keeps the v0.3.15 MAC/1 context architecture and closes the remaining gap that prevented an older authenticated local MongoDB installation from becoming the credential-free `LOCAL_HOST` runtime without manual operator steps.

## Zero-touch activation

`prepare_mongodb_runtime()` now performs this sequence automatically on the supported managed Linux host:

1. remove only obsolete MangoMe credential/binding residue;
2. pin the canonical database identity to `mangome`;
3. prove the configured MongoDB endpoint is loopback;
4. prove the active TCP listener is loopback-only;
5. if MongoDB authorization is still enabled, require root and a simple standalone `mongod.service` security configuration;
6. create a timestamped backup of `/etc/mongod.conf`;
7. change only `security.authorization` to `disabled`;
8. restart `mongod.service` once;
9. prove loopback-only scope again;
10. verify anonymous LOCAL_HOST access and canonical indexes.

The automatic host transition can be disabled with `MANGOME_ZERO_TOUCH_HOST_MIGRATION=0`.

## Hard stops

The migration fails closed and does not weaken MongoDB authorization when any of these conditions is present:

- a non-loopback MongoDB listener;
- non-root runtime;
- missing `systemctl` / inactive `mongod.service`;
- command-line `--auth`;
- ambiguous `mongod.conf`;
- `security.keyFile`, `clusterAuthMode` or `transitionToAuth`;
- non-loopback MongoDB URI.

MangoMe never edits firewall/network configuration, `dbPath`, storage/logging configuration, unrelated databases, or MongoDB users/roles during this host migration.

## Legacy cleanup

For `LOCAL_HOST`, the former credential lifecycle is obsolete. Zero-touch removes only these MangoMe-local artifacts when present:

- `~/.config/mangome/mongodb-uri`
- `~/.config/mangome/mongodb-maintenance-uri`
- `~/.config/mangome/database-binding.json`

It also clears the obsolete process bindings `MANGOME_MONGODB_URI_FILE`, `MANGOME_MONGODB_URI`, `MANGOME_ADOPT_EXISTING_DATABASE`, and `MANGOME_ZERO_TOUCH_LOCAL_PROVISION` before managed client configuration is regenerated.

## Reset integration

The explicitly confirmed `database-reset` now runs zero-touch LOCAL_HOST readiness first. The destructive allowlist remains exact:

```text
mangome
mangome_uai_eval
```

No other database is an eligible reset target. `mangome_uai_eval` is never adopted, repaired or migrated; schema drift remains fail-closed.

## Repository cleanup

`__WEBUPLOAD_META__/` was packaging metadata and is not product source. Remove that directory from GitHub `main`; v0.3.16 web-upload deltas no longer contain upload metadata inside the repository tree.

## Agent guidance cleanup

The canonical and packaged MangoMe Skill surfaces are updated together for v0.3.16. They remove the old credential-adoption/bootstrap-authority guidance, pin LOCAL_HOST to canonical database `mangome`, retain legacy schema-drift fail-closed behavior, and document MAC/1 as the worker-context compiler.
