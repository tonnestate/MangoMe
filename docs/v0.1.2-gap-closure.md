# v0.1.2 gap closure

This release closes the concrete gaps found in the 2026-09-24 repository review.

## Closed

- plan enforcement now persists beyond `start_slice`;
- verifier/owner authority can no longer be obtained by changing an actor string alone;
- evidence is typed, verdict-aware and untrusted until attested;
- gate audit fields are part of the canonical schema;
- contract graph edges are typed and validated;
- effective family contribution state is queryable;
- project-wide deterministic status is queryable;
- Big-Bang identifiers are generic/configurable;
- Big-Bang Git discovery and non-destructive reconciliation are available;
- schema migration is operational rather than just a version field;
- mutable state has revision/CAS protection;
- slice dependencies can require DONE, VERIFIED or ACCEPTED;
- health/readiness exists;
- MCP v2 client surface is covered in CI;
- GitHub workflow and Skill mirror are included under `.github`.

## Intentionally deferred

These are next-stage integrations, not unresolved correctness holes in the v0.1.2 core:

- transport-native IAM/OAuth/scoped MCP authorization;
- long-running change-stream/materialized-view daemon;
- provider-specific IntakeGov/CogC/OmniRoute adapters;
- external ChatGPT/Claude/Gemini reviewer invocation;
- UI/dashboard;
- deeper Git history semantic reconstruction;
- OpenSpec/Beads concrete adapters.

The current runtime-role/capability boundary is suitable for controlled self-hosted deployment, but it should not be presented as a full internet-facing IAM system.
