# MangoMe v0.3.20 — Correctness Recovery

This release is a bounded repair of v0.3.19 findings. It adds no new agent subsystem.

## Closed findings

1. **Concurrent admission identity:** Project, Family and per-Family Slice identity now use atomic get-or-create plus unique database constraints; `InMemoryStore` enforces the same domain uniqueness.
2. **Prompt identity:** normalized prompt fingerprints are admission/dedup hints only. Existing matches return `EXISTING_WORK_CANDIDATE`; durable continuation requires explicit `work_ref`.
3. **LOCAL_HOST assurance boundary:** LOCAL_HOST is `COOPERATIVE_HOST`, not tamper-resistant verification. Direct host/database writers are inside the trust boundary. `MANGOME_RUNTIME_ROLE=FULL` is no longer a privileged aggregate role.
4. **Read purity/scaling:** `status()` is projection-only. Workspace admission lookup no longer calls `project_overview/status` recursively and new Projects persist an indexed `workspace_root`.
5. **Release gate:** stale tests are aligned to the current architecture; CI includes a real MongoDB integration job and concurrent-admission regression.

## Migration behavior

New unique indexes are fail-closed. If a pre-v0.3.20 database already contains duplicate logical identities, index creation must fail rather than silently merge or delete canonical records. Repair such data explicitly before retrying the upgrade.

## Not claimed

v0.3.20 does not introduce service-isolated verifier credentials, cryptographic assurance chains, or hostile same-host protection. Those require a separate deployment-boundary design.
