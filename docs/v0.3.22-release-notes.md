# MangoMe v0.3.22 — Zero-Touch Work Admission

This release removes an agent-facing governance decision observed on a real managed host.

## Closed failure

A workspace could contain unrelated admitted work while the current user request had no matching WorkIdentity. Reconciliation then exposed workspace STATE_FOUND/current-turn authorization state, and a weak agent could stop and ask the user whether to create a new MangoMe entry or provide an existing work reference.

That is now forbidden on the normal worker surface.

## New invariant

```text
WORKSPACE_STATE != CURRENT_REQUEST_IDENTITY
```

MangoMe first checks the exact normalized admission identity of the current request.

- Exact match: continue the known work internally.
- No exact match: the semantic worker facade automatically admits the current request as new operational work.
- The user is not asked to create a MangoMe work entry.
- The user is not asked for an internal work_ref for genuinely new work.
- Missing actor_id on ordinary managed ENTER_WORK is filled from MANGOME_RUNTIME_ACTOR or a stable non-privileged managed-worker identity.

Project overview also exposes that new current-user work does not require a user-supplied work reference or confirmation.

## Preserved boundaries

The precise advanced reconciliation capability remains read-only. Historical/resume recovery still fails closed and is not synthesized from current prompt text. Privileged verifier/controller/owner authority is unchanged.
