# MangoMe v0.3.15 — Native Agent Context Compilation

## Objective

Reduce worker context and repeated Contract-file reads without creating a second truth store or weakening MangoMe's existing governance model.

## Added

- `MAC/1` native capacity-aware agent-context compilation inside MangoMe.
- deterministic projection of current canonical MongoDB Contract generations into clause-level worker units;
- clause provenance with generation id, section path, line span and content hash;
- C0–C3 deterministic criticality with unconditional C0/C1 retention;
- worker capacity profiles for generic small agents, Qwen 4B, Qwen 9B and frontier specialists;
- compression/fidelity receipts and an explicit split/route signal when critical context exceeds worker capacity;
- metadata-only expansion handles: omitted source text remains outside the active worker context;
- transport-budget degradation that folds optional MAC/1 facts before critical normative text.

## Deliberately not added

- no CogC package/runtime dependency;
- no second MongoDB collection or second truth store for clauses;
- no embeddings or LLM classifier in the critical path;
- no automatic Contract repair/migration;
- no routine local Contract-file reread;
- no new authorization or verification mechanism;
- no model-quality claim based only on compression ratio.

## Contract source rule

Routine context uses only the current canonical `contract_generations` text already stored in MongoDB. Local Contract artifacts remain representations and authorized promotion/recovery sources, not the default worker-memory path.

Missing, non-canonical or hash-mismatched Contract generations are not reconstructed from files or agent memory. The reduced context reports the canonical-source problem instead.

## Compatibility

The seven-tool worker MCP facade remains unchanged. Existing `COMPILE_CONTEXT` / `compile_execution_context` calls automatically gain the `agent_context` projection because the integration occurs inside the existing `ContextCompiler`.

UAI/1 remains a transport layer and canonical mutation gates are unchanged.
