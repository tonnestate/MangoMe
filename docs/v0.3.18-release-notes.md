# MangoMe v0.3.18 — Bounded User-Intent Execution Authority

## Problem

EV-U01 showed that ordinary work in an already-admitted workspace was blocked before
the utility test even began. The MCP wrapper required an external CONTROL capability
for `enter_work`, although the governed domain service already admits current user
intent as a task-specific WorkIdentity plus an EXECUTE WorkTurn.

That measured controller availability rather than MangoMe utility.

## Change

`enter_work` no longer requires a separate CONTROL runtime merely because the
workspace already contains canonical MangoMe state.

The resulting authority remains explicitly bounded:

```text
authority     = USER_INTENT_RELAYED_BY_CLIENT
WorkTurn mode = EXECUTE
```

## Unchanged hard boundaries

The delta does not weaken or synthesize:

- VERIFY authority
- MODIFY / normative-truth authority
- CONTROL authority
- OWNER / ACCEPT authority
- ROUTER authority

Workers still cannot self-mint a VERIFY turn through the protected control-plane
surface.

## Evaluation consequence

EV-U01 can now admit ordinary current-user work and measure handover/context utility
without first requiring an artificial host controller.
